# `~/.ingle` and other data locations

Everything a user might want to read or edit by hand lives in **`~/.ingle`**, in plain Markdown and JSON — like
`~/.claude` and `~/.cursor`. Both apps read it; the table says who writes what.

```text
~/.ingle/
├── settings.json        written by the Mac app, read by VS Code
├── bridge-token         written by the Mac app (0600), read by VS Code
├── INGLE.md             the index; regenerated by the Mac app, your notes at the bottom are kept
├── mcp.json             MCP servers (you, the Mac app's Edit/Import buttons, VS Code's Edit mcp.json)
├── rules/               one .md per rule
├── skills/<name>/       one folder per skill, each with a SKILL.md (+ any extra files)
├── commands/            one .md per command (enforced)
├── memory/              one .md per subject + INDEX.md
└── research/            one .md per report + INDEX.md

<your project>/.ingle/
├── rules/               project rules, shown as project/<name>
└── commands/            project commands, shown as project/<name>
```

Path helpers: `IngleHome` in [`../Sources/Ingle/Extensions.swift`](../Sources/Ingle/Extensions.swift) and `paths` in
[`../Extensions/vscode/src/shared/settings.ts`](../Extensions/vscode/src/shared/settings.ts). The shared parsing
rules (frontmatter, slugs, secret filter) are ported line by line between Swift and
[`../Extensions/vscode/src/tools/frontmatter.ts`](../Extensions/vscode/src/tools/frontmatter.ts).

**Frontmatter** everywhere means: a first line `---`, then `key: value` lines, then `---`. Values are single-line;
surrounding double quotes are stripped. It is not full YAML.

**Changing formats:** these files are shared by both apps *and* by users' own hand-written files. Open an issue
before changing a format ([../CONTRIBUTING.md](../CONTRIBUTING.md)), keep old files readable, and update both
parsers.

## `settings.json`

Written by `SettingsMirror` ([`../Sources/Ingle/SettingsMirror.swift`](../Sources/Ingle/SettingsMirror.swift))
whenever a setting or MCP status changes; read by `loadSettings()` in VS Code, which fills anything missing from
defaults. Permissions `0600` because it can contain a Brave Search key. Don't edit it — your changes are overwritten;
change settings in the Mac app instead.

```json
{
  "assistants": [
    { "id": "daily", "name": "Ember", "model": "hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ4_XS",
      "persona": "WHO YOU ARE: …", "contextLength": 32768 },
    { "id": "hard", "name": "Flint", "model": "qwen3.8:27b-mlx",
      "persona": "WHO YOU ARE: …", "contextLength": 32768 }
  ],
  "autocompleteModel": "qwen2.5-coder:1.5b-base",
  "enginePath": "/Applications/Ingle.app/Contents/Resources/OllamaRuntime/ollama",
  "keepAlive": "15m",
  "mcpDisabled": [],
  "mcpStatus": { "filesystem": { "state": "running", "tools": ["read_file", "list_directory"] } },
  "memory": { "askFirst": false, "enabled": true },
  "serverURL": "http://localhost:11434",
  "smartMatching": true,
  "useClaudeSkills": true,
  "userName": "Your Name",
  "web": { "braveKey": "", "onByDefault": true, "provider": "duckduckgo", "searxngURL": "" },
  "workspaceFolders": ["~/Projects"]
}
```

`enginePath` points at the updated engine in `~/Library/Application Support/Ingle/Engine/current/ollama` when one
is installed. `mcpStatus` lets the VS Code `/mcp` dialog show what's connected in the Mac app.

## `bridge-token`

A single line: a random 64-character hex secret, created on the Mac app's first launch with permissions `0600`.
The VS Code extension sends it as `X-Ingle-Token` to the editor bridge. Delete it and restart the Mac app to
rotate it. See [architecture.md](architecture.md#the-editor-bridge).

## `INGLE.md`

The short index the assistant sees on every request (`IngleManifest.refresh` in
[`../Sources/Ingle/Manifest.swift`](../Sources/Ingle/Manifest.swift)). The Mac app rewrites it on every message,
with: tools you always have, Terminal tools, Mac control (on/off), MCP tools, commands, always-on rules in full,
the rules index, skills, MCP servers and their state, the research index, recent chat titles and the memory index.

Everything **below this line is yours** and is kept and sent to the assistant (both apps):

```markdown
<!-- Your notes: everything below this line is kept and sent to the assistant. -->
I use pnpm, not npm. My main project is in ~/Projects/your-project.
```

The VS Code extension doesn't write `INGLE.md`; it builds an equivalent index in memory (`indexPrompt` in
[`../Extensions/vscode/src/engine/prompt.ts`](../Extensions/vscode/src/engine/prompt.ts)) and reads your notes from
the file.

## Rules

`~/.ingle/rules/<name>.md` (and `<project>/.ingle/rules/<name>.md` as `project/<name>`):

```markdown
---
description: Writing React components
always: false
---

Use function components and hooks. Keep components under 150 lines. Co-locate tests as Component.test.tsx.
```

- `always: true` → included in full in every chat ("Rules you always follow").
- `always: false` → listed in the rules index by name and description; matched automatically when relevant, or
  loaded by the model with `use_rule`.
- A file with **no frontmatter** is an always-on rule.
- `name:` is optional (defaults to the file name).
- Settings → Extensions → Rules (Mac) can create, open and toggle them. An older single `~/.ingle/rules.md` is
  migrated once to `rules/general.md`.

## Skills

`~/.ingle/skills/<name>/SKILL.md`, the same layout as Claude's skills, so existing skills work unchanged. If
**Also use my skills in ~/.claude/skills** is on (default), `~/.claude/skills/*/SKILL.md` are read too; on a name
clash the first found (Ingle's) wins.

```markdown
---
name: code-review
description: Review a change for bugs, security issues and readability. Use when asked to review code or a PR.
---

# Code review

1. Read the diff and the files it touches.
2. Check error handling, edge cases and tests.
3. Report findings as: must fix / should fix / nit.
```

- The skills index (name and the first ~110 characters of the description) is in every prompt; `use_skill` loads
  the full text (up to 30,000 characters on Mac), followed by a list of other files in the skill folder, which the
  model can open with `read_file` (VS Code reads them freely).
- `/skill-name your request` forces a skill; matched skills are attached automatically.
- `skill_create` writes `~/.ingle/skills/<slug>/SKILL.md` after you approve; `replace: true` overwrites.
- `/skill-reload` re-reads skills, rules and MCP servers.

## Commands

`~/.ingle/commands/<name>.md` and `<project>/.ingle/commands/<name>.md`. Format and behaviour:
[commands.md](commands.md#the-file-format).

## Memory

`~/.ingle/memory/<subject>.md` — one file per subject (`about-me`, `preferences`, `work`, `projects`, `people`, or
anything else), each a one-line description and one fact per line:

```markdown
---
description: How they like to work
---

- Prefers British English and short answers
- Uses pnpm and Vitest
- Works on ~/Projects/your-project most days
```

- File names are slugs: lower case, letters and digits, `-` between words, at most 60 characters
  (`MemoryStore.slug`, `slug()`).
- `INDEX.md` is regenerated after every change for browsing in Finder; it's never read as a memory.
- The memory index (file names, descriptions, fact counts) is in every prompt; `memory_search` scores lines by word
  overlap; matching files are attached automatically (up to 4,000 characters).
- `memory_save` appends one fact (skipping exact duplicates); `memory_rewrite` replaces a file; `memory_forget`
  removes lines containing some text.
- **Secret filter:** saves and rewrites are refused if the text contains "password", "passcode", "pin code",
  "api key", "secret key", "private key" or "token:", or a run of 13–19 digits (card numbers, spaces and dashes
  ignored). See [security-and-privacy.md](security-and-privacy.md#memory-and-secrets).
- Settings → Web & Memory: switch memory off, **Ask before saving**, open the folder, **Forget Everything…**.

## Research reports

`~/.ingle/research/<YYYY-MM-DD>-<slug>.md`, written by `report_save` (offered only when Web is on):

```markdown
---
title: Local model tool-calling reliability
description: Fewer tools per turn and correct parsers matter more than the quant
date: 2026-11-03
---

# Local model tool-calling reliability

- Accuracy falls from ~85% with 5 tools to ~45% with 20 …

## Sources
https://example.com/paper
```

The research index (newest 15) is in every prompt; `report_search` and `report_read` recall them; matching reports
are attached automatically (up to 5,000 characters). `INDEX.md` is regenerated for browsing.

## `mcp.json`

The same format as Claude Desktop and Cursor:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "~/Projects"],
      "env": {}
    }
  }
}
```

- Only **stdio** servers (with a `command`) are supported; remote (URL) entries are skipped.
- Both apps also read `~/.cursor/mcp.json` and `~/.claude.json` (never written); Ingle's own file wins on a name
  clash. The source is shown in the `/mcp` dialog.
- Settings → Extensions → MCP (Mac): **Edit Config…**, **Import from Claude Desktop** (copies stdio servers from
  `~/Library/Application Support/Claude/claude_desktop_config.json` without overwriting), **Reload**, per-server
  switches (stored in the Mac app's preferences and mirrored to `settings.json` as `mcpDisabled`).
- How servers are started and used: [mac-app.md](mac-app.md#mcp-servers), [vscode-extension.md](vscode-extension.md#mcp).

## Other data locations

| What | Where | Notes |
|---|---|---|
| Mac chats | `~/Library/Application Support/Ingle/chats.json` | All conversations, JSON (`[Conversation]`). New stored properties must be optional so old files still decode. |
| Mac chat images | `~/Library/Application Support/Ingle/images/` | JPEGs (≤ 1,600 px) referenced by file name from messages. Not cleaned up when a chat is deleted. |
| Updated engines | `~/Library/Application Support/Ingle/Engine/{current,previous,staging}` | See [engine.md](engine.md#engineupdater-keeping-ollama-current). |
| Engine log | `~/Library/Logs/Ingle/ollama.log` | Appended by the bundled engine started by the Mac app (not rotated). |
| Mac settings | macOS preferences for Ingle's bundle identifier (UserDefaults) | Keys in `Prefs.K`, plus `checkEngineUpdates`, `engineLastCheck`, `engineNotified`, `mcpDisabledServers`, `modelProfiles`. |
| VS Code chats | VS Code's global storage for the extension: `chats-<sha1 of workspace path, 16 hex>.json` | Per workspace, the 50 most recent non-empty chats. Tied to the extension's publisher name — keep `VSCODE_PUBLISHER` stable. |
| VS Code small state | VS Code `globalState`: `ingle.assistant`, `ingle.think` | Last assistant and Think choice. |
| Models | `~/.ollama/models` | Ollama's store, shared with any other Ollama. Settings → Models can delete them; menu bar → More → Open Model Folder. |
| Cached engine for builds | `~/.local/share/ingle-runtime/` | `build.sh` keeps an unslimmed copy so rebuilds work without the Ollama app. Delete it to make the next build download a fresh engine. |
| `ollama` command | `~/.local/bin/ollama` → the engine inside `/Applications/Ingle.app` | Symlink made by `./build.sh --install`. |
| Temporary files | the system temp folder | Screenshots, AppleScript files, pasted VS Code attachments (`ingle-<uuid>/`), engine downloads. |

**Removing everything:** quit Ingle, delete `/Applications/Ingle.app`, `~/.ingle`,
`~/Library/Application Support/Ingle`, `~/Library/Logs/Ingle`, `~/.local/share/ingle-runtime`,
`~/.local/bin/ollama`, and uninstall the VS Code extension. Models in `~/.ollama/models` are shared with Ollama, so
delete them only if you don't use Ollama elsewhere.

## Trade-offs

| We chose | We gave up | Why |
|---|---|---|
| **One file per rule, skill, command and memory subject** | A single structured settings file or database | Readable and editable in any editor, easy to share or version with a project, toggled or deleted individually; both apps can write without clobbering one big file. Searching and indexing cost a directory scan per request, which is fine at the hundreds-of-files scale. |
| A **minimal frontmatter parser**, not YAML | Lists, nesting and multi-line values | Two identical, dependency-free parsers (Swift and TypeScript) are easy to keep in step; comma-separated values cover every current need. |
| **Claude's skill format** and **Claude Desktop/Cursor's MCP format** | Ingle-specific features in those files | Existing skills and servers work unchanged, and users aren't locked in. |
| Settings stay in **UserDefaults**, mirrored to JSON | One source of truth on disk | SwiftUI's `@AppStorage` is the natural home for settings; the mirror gives the extension what it needs with one writer. |
| **Memory as plain Markdown** | Encryption at rest | You can see and correct exactly what the assistant knows about you. FileVault protects it at rest; anything running as you can read it. |
| Chats **outside** `~/.ingle` for now | Sharing history between apps | Simplest to ship; planned in [roadmap.md](roadmap.md#shared-chat-storage-in-ingle). |
